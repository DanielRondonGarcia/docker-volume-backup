# Job Lease Diagnostics

## Goal

Make interrupted backup and restore jobs explain what was actually observed when a Docker or native worker fails to report a terminal result before its lease expires.

## Problem

The Control Plane currently reduces every expired worker lease to the generic message `Worker lease expired before terminal status was reported.` The message is safe but does not preserve enough bounded context to distinguish worker interruption, renewal failure, lost connectivity, or an unreported runtime error.

## Why

Operators need actionable evidence for scheduled jobs on Docker hosts and client operating systems without exposing lease tokens, credentials, repository secrets, or unverified root-cause claims.

## Scope

- Capture safe lease lifecycle context and the last known worker/progress state.
- Transport worker renewal failures and terminal-report failures when the Control Plane is reachable.
- Project a stable recovery code and human-readable diagnostic details through the existing job API/UI.
- Keep the fail-closed `worker_interrupted` behavior and support Docker and native workers through the shared worker service path.
- Add regression coverage for SQLite/in-memory recovery, worker renewal diagnostics, API projection, and the Jobs log panel.

## Constraints

- Never persist lease tokens, credentials, secrets, raw repository URLs, or unbounded exception text.
- Do not claim that Rclone, Restic, Docker, Kubernetes, or the native filesystem failed unless the worker reported that evidence.
- Preserve the existing lease duration, ownership checks, retry safety, and compatibility identifiers.
- Preserve unrelated `.atl/`, `.codegraph/`, `.playwright-mcp/`, and `__pycache__/` workspace changes.
- Browser/deployment verification is optional and must be reported separately from unit evidence.
